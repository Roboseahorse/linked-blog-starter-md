## The CPU

The processor (aka the **Central Processing Unit** or **CPU**) is made up of a few key components, each with its own job:

- **Control Unit**
- **Buses**
- **Arithmetic-Logic Unit (ALU)**
- **Dedicated registers**

![[Media/cpu-overview.jpeg|330]]

---

## Control Unit

- The part of the processor that **coordinates the activity of all other components**
- Sends **control signals** along the control bus to the rest of the computer

![[Media/control-unit.jpeg|338]]

---

## What is a Bus?

- A bus is a series of connectors that **transfer signals between internal components**
- Usually made up of **8, 16, 32 or 64 lines**

![[Media/bus-diagram.png]]

### System Bus

The system bus is actually **three separate buses**, each carrying something different:

- **Control bus** – control signals
- **Address bus** – addresses
- **Data bus** – data

![[Media/system-bus.png]]

### Control signals include...

- **Memory read** – pulls data from the addressed RAM location onto the data bus
- **Memory write** – writes data from the data bus into the addressed RAM location
- **Bus request** – a device asking for use of the data bus
- **Bus grant** – the CPU granting access to the data bus
- **Clock** – keeps everything synchronised

---

## Arithmetic-Logic Unit (ALU)

The **"problem solving"** part of the processor. Handles arithmetic, logical, and shift operations on data.

- **Arithmetic operations:** Add, Subtract, Multiply, Divide
- **Logical operations:** AND, OR, NOT, XOR
- **Shift operations:** move bits left or right within a register

![[Media/alu-diagram.png]]

---

## The Accumulator

- Results from the ALU need somewhere to go
- Instead of writing back to "slow" main memory, the processor has **super-fast registers** for temporary storage
- This lets the processor **immediately reuse** results in later calculations (e.g. `2 + 3 + 4`)
- For simplicity, we treat the processor as having **one general-purpose register** — the **accumulator**

![[Media/accumulator.png]]

---

## Executing Instructions

Running a sequence of instructions means the processor has to juggle a few pieces of info at once:

- The **current instruction** being executed
- The **address** of any data it needs, and the **data itself**
- The **address of the next instruction** to run

---

## Dedicated Registers

| Register | Full name | Role |
|---|---|---|
| **PC** | Program Counter | Holds the memory address of the **next instruction** to be executed |
| **CIR** | Current Instruction Register | Holds the current instruction (split into **opcode** + **operand**) |
| **MAR** | Memory Address Register | Holds the address the processor needs to **fetch/store** data to or from |
| **MDR** | Memory Data Register | Temporarily holds data moving **between processor and memory** |
| **ACC** | Accumulator | Holds **intermediate results** of an instruction |

## Executing Instructions (recap)

- The processor's job is to **carry out instructions from programs stored in memory**
- The **Control Unit** coordinates the other components — like a **conductor directing an orchestra** 🎼

---

## The Fetch-Execute Cycle

- Processors work through **defined stages** to carry out each instruction
- This cycle **repeats continuously**, once per instruction, for the whole program

![[Media/fetch-execute-cycle.png|413]]

### Fetch (Steps 1–4)

1. Address of the next instruction is copied from the **PC** → **MAR**
2. The instruction at that address is copied to the **MDR**
3. At the same time, the **PC is incremented**
4. Contents of the **MDR** are copied to the **CIR**

> [!note] Visual cue
> Blue lines on the diagram show which connections data travels along during this stage.

![[Media/fetch-execute-annotated.png|364]]

### Decode (Steps 5–7)

5. The instruction held in the **CIR** is decoded
6. It's split into **opcode** and **operand** to work out the instruction type — extra data is fetched from memory if needed
7. That data is passed to the **accumulator**

- The **opcode** specifies the operation to carry out
- The **operand** holds either:
	- the **address** of the data to use → copied to the **MAR**, or
	- the **actual data** to operate on → passed to the **MDR**

With the instruction sitting in the CIR, the Control Unit can now work out exactly what needs to happen to carry it out.

### Execute (Step 8)

- The instruction is **executed**
- The result is held in the **accumulator** or **stored in memory**
